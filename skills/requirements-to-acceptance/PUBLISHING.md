# 需求到验收：使用与发布

将题目截图、需求文档及补充说明转成可追溯的交付说明。完整工作流包括复述要求、由另一位 Agent 独立评定、修订理解、制定完成流程计划及验收。

## 使用

将本目录中的 `SKILL.md` 放入所用 Agent 支持的技能目录，并按该环境的方式加载 `requirements-to-acceptance`。

可使用以下请求：

- 根据这些题目截图复述要求，请另一位 Agent 对照原文评定，再给出完成流程计划和验收方法。
- 对照需求检查我的成果，列出遗漏，并区分不通过、未验证和缺少输入的阻塞项。
- 两份说明的截止时间和格式不同，请保留冲突，先推进不受影响的工作。

技能正文无需额外脚本或 API 密钥。独立评定需要运行环境提供多 Agent 能力；没有可用的独立 Agent 时，必须说明评定未执行，并把计划标为暂定。

## 魔搭发布信息

- 作品名称：需求到验收｜截图与文档交付助手
- 英文标识：`requirements-to-acceptance`
- 分类：开发工具；平台提供文档处理分类时也可使用该分类。
- 标签：需求分析、验收测试、截图理解、项目交付。

发布简介：

读取题目截图、需求文档及补充说明，先复述要求，交由另一位 Agent 独立评定并修订，再给出完成流程计划和验收用例。处理规则冲突、条件限制、提交依赖及证据缺口，适用于比赛、课程项目和产品需求梳理。

## 比赛提交

1. 在题目提测弹窗获取本队当前验证行，保留完整原文。
2. 将验证行原样独占一行追加到 `SKILL.md` 正文末尾。不要放进 YAML、代码块、引号、列表或表格，后面不要再添加说明。
3. 将该文件打包成 ZIP，根目录直接放置 `SKILL.md`，不包含本说明文件，也不套文件夹。
4. 在魔搭社区发布公开 Skill，从实际作品页面复制链接，保留页面实际使用的 `@`，移除作品链接的查询参数和锚点。
5. 返回题目填写实际作品页链接并提交，在提测记录中查看本次提交的最终结果。

用于本题的验证行已写入 `SKILL.md` 正文末尾。发布前应确认该行仍与本队当前验证行一致。本地结构校验、GitHub 提交、魔搭公开发布和题目评测通过是不同状态，分别核验。

题目截图中的分值和验证行时效描述存在差异；以当前题目页面的有效规则和实际返回结果为准，不自行据截图顺序确定版本。
